# kcptun-rs Auto Optimizer

اسکریپتی برای پیدا کردن بهترین تنظیمات `kcptun-rs` بین دو سرور.

## کاری که می‌کنه

1. `kcptun-rs` رو از سورس build می‌کنه و باینری‌ها رو با SHA256 به سرور دوم منتقل می‌کنه.
2. یه baseline مستقیم با `iperf3` بین دو سرور می‌گیره (بدون تانل) تا سرعت خط مشخص بشه.
3. به‌صورت greedy و مرحله‌به‌مرحله این پارامترها رو تست می‌کنه و بهترین رو انتخاب می‌کنه:
   - `--mode`
   - `--mtu`
   - `--sndwnd` / `--rcvwnd`
   - `--sockbuf`
   - `--nocomp` و `--smuxver`
4. در پایان، بهترین ترکیب و دستورهای آماده برای سرور و کلاینت رو چاپ می‌کنه.

## پیش‌نیاز

- دو سرور Ubuntu 22 یا 24 با دسترسی root
- دسترسی SSH از سرور خارج به سرور ایران (پورت و رمز یا کلید)
- `bash`، `curl`، `sshpass` روی سرور خارج (اسکریپت خودش نصب می‌کنه)

## اجرا

حداقل چیزی که لازمه:

```bash
sudo IRAN_IP=<iran-ip> IRAN_PASS=<password> ./v3.sh
```

بقیه‌ی متغیرها اختیاری‌ان.

### متغیرهای محیطی

#### اتصال به سرور ایران

| متغیر      | پیش‌فرض | توضیح                    |
|------------|---------|--------------------------|
| `IRAN_IP`  | —       | IP سرور ایران (اجباری)   |
| `IRAN_USER`| `root`  | یوزر SSH                 |
| `IRAN_PASS`| —       | پسورد SSH (اجباری)       |
| `IRAN_PORT`| `22`    | پورت SSH                 |

#### حالت اجرا

| متغیر   | پیش‌فرض | توضیح                                              |
|---------|---------|----------------------------------------------------|
| `DEBUG` | `0`     | اگه `1` باشه، بعد از هر مرحله pause می‌کنه و وضعیت رو نشون می‌ده |

#### Override کردن پارامترها (skip کردن sweep)

هر کدوم از اینا که ست بشه، مرحله‌ی sweep مربوطه skip می‌شه و همون مقدار استفاده می‌شه.

| متغیر      | مقادیر مجاز                          | مثال              |
|------------|--------------------------------------|-------------------|
| `MODE`     | `fast`, `fast2`, `fast3`, `normal`, `manual` | `MODE=fast3`     |
| `MTU`      | عدد                                  | `MTU=1400`        |
| `WIN`      | `snd/rcv`                            | `WIN=2048/2048`   |
| `SOCKBUF`  | عدد (بایت)                           | `SOCKBUF=8388608` |
| `NOCOMP`   | `on`, `off`                          | `NOCOMP=on`       |
| `SMUXVER`  | `1`, `2`                             | `SMUXVER=2`       |

اگه فقط یکی از `NOCOMP` یا `SMUXVER` ست بشه، مرحله‌ی ۵ فقط روی ترکیب‌هایی که با مقدار داده‌شده سازگارن اجرا می‌شه (نه کامل skip). اگه هر دو ست بشن، مرحله کلاً skip می‌شه.

### مثال‌ها

فقط mode رو قفل کن و بقیه رو sweep کن:

```bash
sudo MODE=fast3 \
  IRAN_IP=<iran-ip> IRAN_PASS=<password> \
  ./v3.sh
```

mode و mtu رو قفل کن، بقیه sweep:

```bash
sudo MODE=fast3 MTU=1400 \
  IRAN_IP=<iran-ip> IRAN_PASS=<password> \
  ./v3.sh
```

همه چیز رو دستی بده (بدون هیچ sweep، فقط یه تست):

```bash
sudo MODE=fast3 MTU=1400 WIN=2048/2048 SOCKBUF=8388608 NOCOMP=on SMUXVER=2 \
  IRAN_IP=<iran-ip> IRAN_PASS=<password> \
  ./v3.sh
```

با debug و فقط تست mode:

```bash
sudo DEBUG=1 MODE=fast3 \
  IRAN_IP=<iran-ip> IRAN_PASS=<password> \
  ./v3.sh
```

## خروجی نهایی

اسکریپت در انتها:

- baseline مستقیم بین دو سرور رو چاپ می‌کنه
- نتیجه‌ی هر مرحله و برنده‌ی هر مرحله رو نشون می‌ده
- بهترین ترکیب کلی و سرعتش رو می‌ده
- دستور آماده‌ی سرور و کلاینت رو با پارامترهای برنده چاپ می‌کنه که می‌تونی مستقیم توی سرویس واقعی کپی کنی

## نکته‌ها

- در طول تست، همه‌ی پروسه‌های `iperf3` و `kcptun` روی هر دو سرور با `pkill` پاک می‌شن. اگه سرویس `kcptun` واقعی روی همون پورت‌ها داری، قبل از اجرا خاموشش کن.
- `--sockbuf 16777217` توی لاگ سرور به `effective recv=33554434 send=33554434` رُند می‌شه، یعنی عملاً معادل `33554432` هست.
- `--key` هر بار تصادفی ساخته می‌شه و توی خروجی نهایی چاپ می‌شه.
- `--crypt` ثابت روی `xor` می‌مونه.
