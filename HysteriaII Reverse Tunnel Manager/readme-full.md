# hysteria-tm: راهنمای کامل

این سند همهٔ بخش‌های `hysteria-tm` را توضیح می‌دهد: معماری، پیش‌نیازها، نصب، منوها، پروفایل‌ها، پورت‌ها، بنچمارک، نصب آفلاین، فایل‌های نصب‌شده روی سرور، عیب‌یابی و حذف.

---

## ۱. معماری

اسکریپت روی **سرور ایران** اجرا می‌شود. این سرور نقش میزبان مدیریت را دارد:

- کانفیگ‌ها و سرویس‌های سمت ایران را مستقیم می‌سازد.
- با SSH به سرور خارج وصل می‌شود و کانفیگ‌ها، سرویس‌ها و باینری‌های سمت خارج را از همین مسیر نصب و راه‌اندازی می‌کند.
- هیچ‌وقت رمز SSH را ذخیره نمی‌کند. رمز هر بار موقع اتصال پرسیده می‌شود.

### نوع‌های تانل

| نوع | سرور Hysteria | کلاینت Hysteria | کاربرد |
|---|---|---|---|
| `direct` | خارج | ایران | حالت عادی؛ ایران به خارج UDP می‌فرستد |
| `reverse` | ایران (به‌همراه rbridge) | خارج (به‌همراه rbridge) | وقتی خارج فقط به ایران دسترسی دارد |
| `both` | هر دو | هر دو | ترکیب direct و reverse پشت haproxy روی ایران |

در `reverse`، rbridge روی هر دو سرور اجرا می‌شود. rbridge یک رلهٔ TCP است که اتصال‌های کاربر را از ایران به خارج تونل می‌کند. استخر اتصال‌های آمادهٔ آن در حافظه نگه داشته می‌شود و با بودجهٔ RAM که در ساخت تانل انتخاب می‌کنی تنظیم می‌شود.

### مسیر ترافیک کاربر

- **direct**: کاربر ← پورت TCP روی ایران ← کلاینت Hysteria روی ایران ← (UDP) ← سرور Hysteria روی خارج ← پورت سرویس تو روی خارج (`target_port`)
- **reverse**: کاربر ← پورت TCP روی ایران ← rbridge روی ایران ← (Hysteria) ← rbridge و کلاینت Hysteria روی خارج ← پورت سرویس تو روی خارج

## ۲. پیش‌نیازها

### سرور ایران
- Ubuntu با دسترسی root
- اتصال به اینترنت یا فایل‌های آفلاین (بخش ۸)
- پکیج‌های `apt` که اسکریپت خودش نصب می‌کند: `iperf3`، `openssl`، `curl`، `haproxy` (فقط برای both)، `python3-paramiko`، و `nft` برای تست hop

### سرور خارج
- Ubuntu یا هر توزیع با **systemd** و **systemd-run**
- دسترسی SSH (کاربر root یا کاربری با دسترسی sudo کامل)
- `python3` (برای تست hop و سرور تست بنچمارک)
- `iperf3`، `openssl`، `curl` (اسکریپت اگر نباشند نصب می‌کند)

### شبکه
- سرور خارج باید بتواند به IP سرور ایران روی پورت‌های UDP تانل وصل شود (در `direct`) یا برعکس (در `reverse`). این را در سرویس‌دهنده‌ات چک کن.
- برای `max-stealth`: یک دامنه که رکورد A آن به سرور مربوطه اشاره کند. اگر گواهی آماده نداری، پورت TCP 80 باید موقع صدور گواهی آزاد باشد. اگر مشغول باشد، اسکریپت منتظر می‌ماند تا آزاد شود و قبل از ادامه از تو می‌خواهد سرویس را موقتاً متوقف کنی.

## ۳. نصب و اجرا

### پکیج رسمی

پکیج رسمی در این آدرس است:

```
https://github.com/URT19/MyLinuxTools/raw/refs/heads/main/HysteriaII%20Reverse%20Tunnel%20Manager/hysteria-tm-0.9.2.tar.gz
```

این پکیج شامل اسکریپت و سه فایل آفلاین است، پس دیگر لازم نیست Hysteria، rbridge یا installer را جداگانه دانلود کنی:

```
hysteria-tm/
├── hysteria-tm
└── hysteria-tm-files/
    ├── hysteria-linux-amd64        (Hysteria v2.13.0)
    ├── install_server.sh           (اسکریپت نصب رسمی Hysteria)
    └── rbridge-linux-x86_64        (rbridge 0.1.0)
```


### آماده‌سازی روی سرور ایران

۱. پکیج را دانلود کن:
```bash
curl -fL -o hysteria-tm.tar.gz "https://github.com/URT19/MyLinuxTools/raw/refs/heads/main/HysteriaII%20Reverse%20Tunnel%20Manager/hysteria-tm-0.9.2.tar.gz"
```


۳. پکیج را باز کن و وارد پوشه شو:
```bash
tar -xzf hysteria-tm.tar.gz
cd hysteria-tm
```

۴. **وارد پوشه شو** (این مرحله را جا نینداز) و اسکریپت را با root اجرا کن:

```bash
cd hysteria-tm
chmod +x hysteria-tm
sudo ./hysteria-tm
```

اسکریپت باید با root اجرا شود. اگر root نباشد، پیام خطا می‌دهد و خارج می‌شود.

**نکته:** اگر اجرای `python3 hysteria-tm` را از پوشهٔ `/root` بزنی، پایتون پوشهٔ `hysteria-tm` را می‌بیند و خطای `can't find '__main__' module in '/root/hysteria-tm'` می‌دهد. با `cd hysteria-tm` و `./hysteria-tm` این خطا رفع می‌شود.

**نکتهٔ SSH:** نصب و بنچمارک چند دقیقه طول می‌کشد. اگر SSH قطع شود، اسکریپت هم متوقف می‌شود. قبل از اجرا یک جلسهٔ `tmux` باز کن:
```bash
apt-get install -y tmux
tmux new -s hysteria-tm
```
اگر SSH قطع شد، دوباره وصل شو و با `tmux attach -t hysteria-tm` به همان جلسه برگرد.

### اولین سؤال
قبل از هر کاری، اسکریپت می‌پرسد:

> Is THIS server located in IRAN and is this script running on it? [y/N]

فقط با `y` ادامه می‌دهد. با Enter یا هر چیز دیگر متوقف می‌شود. این تأیید فقط یک سؤال است و موقعیت سرور را بررسی نمی‌کند. اسکریپت برای سرور خارج یا هر سرور دیگری کار نمی‌کند.

### اتصال به خارج
- IP سرور خارج، پورت SSH (پیش‌فرض ۲۲)، کاربر (پیش‌فرض root) و رمز را بده.
- اگر SSH شکست بخورد، می‌توانی **حالت دستی** را انتخاب کنی. در این حالت منو دستورهای لازم برای خارج را یکی‌یکی نشان می‌دهد و تو آن‌ها را در ترمینال خارج اجرا می‌کنی.

### فایل تنظیمات `config-hysteria-tm.json`

اسکریپت جواب‌های تکراری را در `/etc/tunnel-manager/config-hysteria-tm.json` ذخیره می‌کند تا هر بار پرسیده نشوند:

| کلید | معنی |
|---|---|
| `iran_ip` | IP عمومی ایران. فقط یک بار پرسیده می‌شود. تغییرش از منوی اصلی، گزینهٔ 8 |
| `kharej_host` | آدرس سرور خارج. دفعهٔ بعد به‌عنوان پیش‌فرض نشان داده می‌شود (با Enter قبول می‌شود) |

**رمز SSH هرگز ذخیره نمی‌شود** و هر بار پرسیده می‌شود. فایل با دسترسی 600 ساخته می‌شود. سؤال «آیا این سرور در ایران است؟» برای ایمنی در هر اجرا پرسیده می‌شود.

## ۵. ساخت تانل (گزینه ۱)

ترتیب سؤال‌ها:

1. **نام تانل**: فقط حروف کوچک انگلیسی، عدد و خط تیره، حداکثر ۲۰ کاراکتر. نام تکراری قبول نمی‌شود.
2. **Tunnel preset**: یکی از شش ترکیب آماده یا گزینهٔ 7 (custom).
3. **Tunnel type** (فقط در custom): direct، reverse یا both.
4. **Stealth profile** (فقط در custom): stealth-hop، max-stealth یا tcp-lite.
5. **آدرس سرورها**: IP عمومی ایران (از فایل تنظیمات خوانده می‌شود و فقط بار اول پرسیده می‌شود) و IP خارج (از اتصال SSH گرفته می‌شود).
6. **Memory budget**: RAM برای استخر اتصال‌های rbridge. مقدارهای مجاز: 128، 256، 512، 1024، 2048، 4096 MB.
7. **Masquerade**: سایتی که سرور Hysteria وقتی کسی بدون احراز هویت وصل شود به آن نشان می‌دهد. گزینه‌ها: bing، microsoft، wikipedia، apple، آدرس دلخواه (باید از خارج HTTP 200 بدهد)، یا صفحهٔ متنی ساده.
8. **Extra options**: اختیاری، با شماره‌ها (مثلاً `1,3`). ترتیب: SNI guard، ECH، multi-user، masquerade headers، lazy client با TCP Fast Open، BBR، و آمار ترافیک. برای max-stealth گزینه‌های SNI guard و ECH نشان داده نمی‌شوند چون از قبل در پروفایل هستند.
9. **برای max-stealth**: دامنه‌ها، ایمیل ACME و ECH public name.
10. **Target port on KHARJ**: پورت TCP سرویس تو روی خارج که کاربرها باید به آن برسند. مثلاً 443 اگر xray یا sing-box روی `127.0.0.1:443` روی خارج گوش می‌دهد. این پورت باید از قبل باز باشد.
11. **پورت‌های عمومی و Hysteria**: بسته به نوع تانل، پورت TCP عمومی روی ایران و پورت UDP سرور Hysteria پرسیده می‌شود. اگر پورت مشغول باشد، اسکریپت آن را رد می‌کند و یکی دیگر می‌خواهد.

**پورت عمومی:** از نسخهٔ 0.9.1 پیش‌فرض این سؤال **همان پورت سرویس روی خارج** است. مثلاً اگر سرویس روی خارج `2096` است، با Enter پورت عمومی ایران هم `2096` می‌شود و کاربر به `IRAN:2096` وصل می‌شود. برای پورت تصادفی `r` بزن. (در نسخه‌های قبل پیش‌فرض تصادفی بود. تانل‌های قدیمی را از منوی فوروارد پورت‌ها، گزینهٔ 2، به پورت دلخواه ببر.) بعد از ساخت، در پایان خروجی و در منوی فوروارد پورت‌ها جدول «کدام پورت ایران به کدام پورت خارج می‌رود» نشان داده می‌شود.

در پایان، کانفیگ‌ها نوشته می‌شوند، سرویس‌ها راه‌اندازی و بررسی می‌شوند، و اگر سرویسی بعد از شروع بیفتد، اسکریپت دلیلش را از لاگ همان سرویس نشان می‌دهد.

## ۶. پروفایل‌ها

### stealth-hop
- Hysteria با **salamander obfuscation** (رمزگذاری بسته‌ها)
- **پرش پورت UDP**: کلاینت طبق پیش‌فرض Hysteria هر ۳۰ ثانیه به پورت دیگری در بازهٔ ۱۰۰ تایی می‌رود (HOP_COUNT = 100)، و سرور روی همان بازه با `nft` گوش می‌دهد. بازه فقط در Linux و با root کار می‌کند.
- Masquerade به یک سایت واقعی
- نیاز به دامنه ندارد

### max-stealth
- ظاهر HTTP/3 واقعی: گواهی **ACME** (Let's Encrypt) برای دامنه‌ای که مالکش هستی + **ECH** (پنهان کردن SNI واقعی در handshake) + Masquerade
- **بدون** obfuscation و **بدون** mimic (mimic حذف شده است)
- **پورت UDP**: اول 443، اگر مشغول بود 8443، اگر آن هم مشغول بود یک پورت تصادفی آزاد
- نیاز به دامنه با رکورد A
- اگر گواهی معتبر برای همان دامنه روی سرور باشد، اسکریپت پیشنهاد استفاده از آن را می‌دهد و گواهی جدید نمی‌گیرد

### tcp-lite
- فقط TCP از طریق تانل. هیچ UDP از تانل عبور نمی‌کند
- کلاینت lazy و obfuscation از نوع gecko
- سبک‌ترین پروفایل

### ایمیل ACME
پیش‌فرض `admin@<دامنه>` است. Let's Encrypt دامنه‌های نامعتبر مثل `.fake` را قبول نمی‌کند.

## ۸. نصب آفلاین و نصب آنلاین

### فولدر فایل‌های آفلاین
پکیج رسمی (بخش ۳) این پوشه و فایل‌هایش را از قبل دارد. فقط اگر می‌خواهی نسخهٔ دیگری از یکی از فایل‌ها را استفاده کنی، کنار اسکریپت پوشهٔ `hysteria-tm-files` را بساز و فایل‌ها را داخلش بگذار:

```
hysteria-tm-files/hysteria-linux-amd64        باینری Hysteria برای CPU سرور (x86_64 یا aarch64)
hysteria-tm-files/install_server.sh           اسکریپت نصب رسمی Hysteria
hysteria-tm-files/rbridge-linux-x86_64        باینری rbridge
```

- `hysteria-linux-amd64` از صفحهٔ releases پروژهٔ HyNetworks برداشته می‌شود (نسخهٔ v2.13.0 توصیه می‌شود).
- `install_server.sh` را از `https://get.hy2.sh/` بگیر و به همین نام ذخیره کن.
- اگر پوشه کامل نباشد، اسکریپت می‌گوید چه فایلی کم است.

### نصب Hysteria روی ایران
وقتی Hysteria پیدا نشود، یا باینری کار نکند:

- اگر فایل‌های آفلاین کامل باشند، اسکریپت سه گزینه می‌دهد:
  1. نصب از فایل‌های آفلاین (پیشنهادی، بدون اینترنت)
  2. دانلود نسخهٔ ثابت v2.13.0 به‌صورت آنلاین
  3. دانلود آخرین نسخه به‌صورت آنلاین
- اگر فایل‌ها نباشند، نصب آنلاین v2.13.0 در ۴ مرحلهٔ جدا انجام می‌شود:
  1. دانلود `install_server.sh` از `get.hy2.sh` به `/tmp/install_server.sh`
  2. دانلود باینری v2.13.0 به `/tmp/hysteria-linux-amd64`
  3. اجرای `bash /tmp/install_server.sh --local /tmp/hysteria-linux-amd64`
  4. اجرای `hysteria version` برای تأیید
- اگر مرحله‌ها شکست بخورند، می‌توانی یک SOCKS5 proxy بدهی و دوباره امتحان کنی.
- اگر هنوز نشد، راهنمای نصب آفلاین نمایش داده می‌شود و اسکریپت منتظر فایل‌ها می‌ماند.

هر دانلود timeout دارد و هیچ‌وقت بی‌نهایت منتظر نمی‌ماند.

### باینری خراب
اگر فایل `/usr/local/bin/hysteria` وجود داشته باشد ولی اجرا نشود (مثلاً فایل خالی یا برای CPU دیگر)، اسکریپت آن را نشان می‌دهد و با تأیید تو جایگزین می‌کند. این خطا معمولاً با `Exec format error` دیده می‌شود.

### نصب روی خارج
اگر Hysteria روی خارج نصب نباشد یا کار نکند، همان سه مرحلهٔ آنلاین از طریق SSH اجرا می‌شود. اگر شکست بخورد و Hysteria روی ایران سالم باشد، اسکریپت پیشنهاد می‌دهد همان فایل را از ایران به خارج کپی کند. این کار فقط وقتی انجام می‌شود که CPU دو سرور یکی باشد.

### rbridge
- **روی ایران**: اگر `/usr/local/bin/tm-rbridge` نباشد، اول فایل آفلاین را پیشنهاد می‌دهد، بعد دنبال نسخهٔ موجود روی سیستم می‌گردد، بعد دانلود می‌کند، و در آخر منتظر فایل می‌ماند.
- **روی خارج**: اگر نباشد، از فایل آفلاین کپی می‌شود (با تأیید تو) یا مسیر فایل را می‌پرسد.

## ۹. بنچمارک خودکار (گزینه ۶)

### هدف
شش ترکیب را یکی‌یکی می‌سازد، با درخواست‌های واقعی از داخل تانل امتحان می‌کند، امتیاز می‌دهد، و تانل موقت را حذف می‌کند.

### ترتیب اجرا
1. سؤال شروع (پیش‌فرض: خیر)
2. **چک‌لیست وابستگی‌ها** (قبل از هر تستی)
3. دو دامنه: یکی برای سرور خارج (direct) و یکی برای سرور ایران (reverse). باید متفاوت باشند.
4. ایمیل ACME، ECH public name و IP ایران
5. بررسی گواهی‌های موجود
6. پاک‌سازی تانل‌های بنچمارک قبلی
7. شش تست. هر تست: ساخت تانل، بررسی سرویس‌ها، ۵ درخواست ۵۰ کیلوبایتی، امتیاز، حذف تانل
8. ذخیرهٔ نتیجه و نمایش جدول

### چک‌لیست وابستگی‌ها
قبل از شروع، این موارد بررسی و در صورت نیاز نصب می‌شوند. هر مورد ✔ یا ✖ می‌گیرد:

- **ایران**: hysteria اجرا می‌شود؟ · rbridge اجرا می‌شود؟ · iperf3، openssl، curl، haproxy، paramiko · nft و python3
- **خارج**: اتصال SSH · iperf3، openssl، curl، systemd-run، python3 · hysteria اجرا می‌شود؟ · rbridge اجرا می‌شود؟

اگر حتی یک مورد ✖ باشد، بنچمارک شروع نمی‌شود.

### امتیاز
- **۳۰ امتیاز**: نسبت درخواست‌های موفق
- **۳۰ امتیاز**: زمان کل دانلود ۵۰ کیلوبایت از داخل تانل (`time_total`). زیر ۳۰۰ میلی‌ثانیه امتیاز کامل، تا ۲۰۰۰ میلی‌ثانیه کاهش تدریجی
- **۴۰ امتیاز**: زمان تا اولین بایت (`time_starttransfer`). زیر ۱۵۰ میلی‌ثانیه امتیاز کامل

هر دو زمان از کل مسیر عبور می‌کنند (ایران، تانل، خارج و برگشت). زمان اتصال روی localhost دیگر در امتیاز حساب نمی‌شود.

### خروجی
- جدول نتیجه آخرین خروجی است و به ترتیب امتیاز مرتب شده.
- قبل از جدول، بخش «Why tests failed» علت هر تست شکست‌خورده را نشان می‌دهد: آخرین خطوط لاگ هر سرویس و اطلاعات شبکه هر دو سرور (نسخهٔ Hysteria و rbridge، قوانین redirect، شمارندهٔ خطای UDP، بافرها، conntrack، وضعیت ufw).
- فایل JSON کامل نتیجه‌ها در `/etc/tunnel-manager/bench/result-<زمان>.json` روی ایران ذخیره می‌شود.

### نکته
نتیجهٔ بنچمارک فقط برای همان لحظه و همان مسیر معتبر است. تست‌ها ساخت و حذف تانل‌های موقت هستند و روی تانل‌های واقعی تو اثری ندارند.

---

## ۱۰. مدیریت تانل (گزینه ۲)

برای هر تانل:

| گزینه | کار |
|---|---|
| 1 | نمایش وضعیت (هر دو سرور) |
| 2 | شروع |
| 3 | توقف |
| 4 | ری‌استارت |
| 5 | تغییر وزن haproxy (فقط both) |
| 6 | فوروارد پورت‌ها: نمایش، اضافه، بازنویسی، حذف |
| 7 | حذف تانل |
| 0 | بازگشت |

بالای این صفحه همیشه جدول فوروارد پورت‌ها نشان داده می‌شود، مثلاً:

```
Port forwards (2):
  1) IRAN 36036  (tcp    ) -> KHARJ 127.0.0.1:2096   [f1]
       rbridge: IRAN 127.0.0.1:24157 <-> Hysteria UDP 55498-55597 <-> KHARJ 127.0.0.1:27848, then KHARJ 127.0.0.1:2096
  2) IRAN 8443   (tcp    ) -> KHARJ 127.0.0.1:3306   [f2]
```

### فوروارد پورت‌ها (گزینهٔ 6)

هر تانل می‌تواند چند فوروارد داشته باشد. هر فوروارد یعنی: کاربر به `IRAN:public` وصل می‌شود و ترافیک به `127.0.0.1:target` روی خارج می‌رسد. همهٔ فوروارد‌های یک تانل از همان اتصال Hysteria استفاده می‌کنند.

| گزینه | کار |
|---|---|
| 1 | اضافه کردن فوروارد جدید: پورت سرویس روی خارج و پورت عمومی روی ایران را می‌پرسد |
| 2 | بازنویسی یک فوروارد: تغییر پورت ایران و/یا پورت خارج (Enter = بدون تغییر) |
| 3 | حذف یک فوروارد (فوروارد آخر قابل حذف نیست؛ در آن حالت کل تانل را حذف کن) |
| 4 | اعمال دوبارهٔ همهٔ کانفیگ‌ها روی هر دو سرور و ری‌استارت سرویس‌ها |

نکته‌ها:
- بعد از هر تغییر، کانفیگ‌ها روی هر دو سرور بازنویسی و سرویس‌ها ری‌استارت می‌شوند. اتصال‌های جاری این تانل چند ثانیه قطع می‌شوند.
- گواهی‌ها و کلیدها دست نمی‌خورند.
- تانل‌های قدیمی (ساخته‌شده با نسخه‌های قبل) خودکار با یک فوروارد `f1` خوانده می‌شوند.
- در تانل‌های reverse، گزینهٔ 4 کانفیگ سرور Hysteria روی ایران را هم بازنویسی می‌کند تا سقف استریم بالا برود (بخش عیب‌یابی را ببین).
- پورت عمومی جدید باید روی ایران آزاد باشد (چک می‌شود). اگر ufw فعال باشد، پورت جدید باز و پورت قدیمی بسته می‌شود.

### حذف تانل
سرویس‌ها را روی هر دو سرور متوقف و حذف می‌کند، فایل‌های تانل را پاک می‌کند، و کانفیگ haproxy آن را برمی‌دارد. Hysteria و rbridge نصب‌شده را پاک نمی‌کند.

## ۱۱. تست سرعت (گزینه ۳)

روی یک تانل ساخته‌شده، سرعت را با Hysteria و iperf3 می‌سنجد. برای این کار سرور iperf3 موقت روی خارج راه می‌افتد.

## ۱۲. فایل‌ها و سرویس‌ها روی سرورها

### روی ایران
| مسیر | محتوا |
|---|---|
| `/usr/local/bin/hysteria` | باینری Hysteria |
| `/usr/local/bin/tm-rbridge` | باینری rbridge |
| `/etc/tunnel-manager/tunnels/<نام>.json` | مشخصات هر تانل |
| `/etc/tunnel-manager/<نام>/` | کانفیگ‌های YAML، فایل‌های ECH و گواهی |
| `/etc/tunnel-manager/acme/<دامنه>/` | گواهی‌های ACME |
| `/etc/tunnel-manager/haproxy/` | کانفیگ haproxy تانل‌های both |
| `/etc/tunnel-manager/bench/` | نتیجه‌های بنچمارک (JSON) |
| `/var/backups/tunnel-manager/` | نسخهٔ پشتیبان فایل‌هایی که جایگزین شده‌اند |
| `/etc/systemd/system/tm-<نام>-*.service` | سرویس‌های تانل |

### روی خارج
| مسیر | محتوا |
|---|---|
| `/usr/local/bin/hysteria` | باینری Hysteria |
| `/usr/local/bin/tm-rbridge` | باینری rbridge (در reverse) |
| `/etc/tunnel-manager/<نام>/` | کانفیگ‌ها |
| `/etc/systemd/system/tm-<نام>-*.service` | سرویس‌های تانل |

### اسم سرویس‌ها
- `tm-<نام>-direct-hy.service`: کلاینت Hysteria (direct، سمت ایران) یا سرور (direct، سمت خارج)
- `tm-<نام>-reverse-hy.service`: سرور Hysteria روی ایران یا کلاینت روی خارج
- `tm-<نام>-reverse-rb.service`: rbridge روی ایران
- `tm-<نام>-haproxy.service`: haproxy (both)

### رمزها و گواهی‌ها
- رمز SSH هیچ‌وقت ذخیره نمی‌شود.
- رمزهای تانل و کلیدهای ECH و ACME روی سرورها ذخیره می‌شوند. فایل‌های کلید با مجوز `0600` ساخته می‌شوند.

## ۱۳. پورت‌ها

| پورت | کجا | کاربرد |
|---|---|---|
| TCP عمومی | ایران | کاربرها به آن وصل می‌شوند (direct و reverse) |
| TCP `target_port` | خارج | سرویس تو که تانل به آن می‌رسد |
| UDP سرور Hysteria | ایران یا خارج | بین کلاینت و سرور Hysteria |
| UDP بازهٔ hop (۱۰۰ پورت) | سرور | در stealth-hop |
| UDP 443 → 8443 → تصادفی | سرور | در max-stealth |
| TCP 80 | سرور | فقط برای صدور گواهی ACME (در صورت نیاز) |

پورت‌های تصادفی از بازهٔ `20000` تا `60000` انتخاب می‌شوند.

## ۱۴. عیب‌یابی

### `can't find '__main__' module in '.../hysteria-tm'`
اسکریپت را از پوشهٔ بیرونی اجرا کرده‌ای. وارد پوشهٔ `hysteria-tm` شو و دوباره اجرا کن:
```bash
cd hysteria-tm
sudo python3 ./hysteria-tm
```

### SSH قطع شد و نصب یا بنچمارک نیمه‌کاره ماند
اگر در `tmux` اجرا کرده بودی، با `tmux attach -t hysteria-tm` ادامه را ببین. اگر نه، اسکریپت را دوباره اجرا کن. بنچمارک قبل از شروع سرویس‌های موقت مانده از اجرای قبلی را پاک می‌کند. برای تانل‌هایی که ساخته شده‌اند، منوی ۴ (وضعیت) را ببین؛ هر تانل اضافه را می‌توانی از منوی ۲ حذف کنی.

### `Exec format error` روی `/usr/local/bin/hysteria`
باینری خالی است یا برای CPU دیگری است. اسکریپت آن را نشان می‌دهد و با تأیید تو جایگزین می‌کند. اگر خودت می‌خواهی دستی پاک کنی: `rm -f /usr/local/bin/hysteria`، بعد اسکریپت را دوباره اجرا کن.

### `no UDP answer` یا `connect error: timeout: no recent network activity`
کلاینت پاسخ UDP از سرور نگرفته. علت‌های رایج:
- پورت UDP سرور از جایی که کلاینت می‌رود باز نیست (فایروال سرویس‌دهنده یا NAT)
- سرور روی پورت دیگری گوش می‌دهد
- مسیر UDP بین دو سرور فیلتر است

برای بررسی: `ss -lunp` روی سرور مقصد را ببین و قوانین فایروال ارائه‌دهنده را چک کن.

### `address already in use` در لاگ یک سرویس
یکی از پورت‌های محلی تانل (مثلاً پورت داخلی یا پورت استخر rbridge) روی یکی از دو سرور از قبل مشغول بوده است.

- قبل از شروع سرویس‌ها، اسکریپت همهٔ پورت‌های گوش‌دهندهٔ تانل را روی هر دو سرور بررسی می‌کند. پورت مشغول با یک پورت آزاد جایگزین می‌شود و پیام آن را نشان می‌دهد.
- اگر در حین اجرا باز هم این خطا دیده شد، بنچمارک همان تست را یک بار دیگر با پورت‌های جدید اجرا می‌کند.
- اگر بعد از این هم شکست خورد، علتش یک سرویس دیگر است که روی همان پورت گوش می‌دهد. با `ss -ltnp` (یا `ss -lunp` برای UDP) روی سرور ببین کدام فرایند پورت را گرفته است.

### به پورت ایران وصل نمی‌شوم (`Connection refused`)
اول مطمئن شو به **پورت عمومی** تانل وصل می‌شوی، نه پورت سرویس. جدول فوروارد پورت‌ها را در منوی مدیریت ببین. روی ایران بررسی کن:
```bash
ss -ltnp | grep ':<پورت عمومی>'
```
اگر پورت عمومی گوش نمی‌دهد، سرویس تانل بالا نیامده است. اگر گوش می‌دهد ولی به سرویس نمی‌رسد، لاگ‌های Hysteria و rbridge را روی هر دو سرور بخوان. روی خارج هم بررسی کن سرویس واقعاً روی `127.0.0.1:<target>` گوش می‌دهد.

### `too many open streams` و اتصال دوبارهٔ مرتب (reverse)
در لاگ کلاینت Hysteria روی خارج پیام `connection closed: too many open streams` و بعد `connected to server` تکراری (حدود هر ۶۰ ثانیه) دیده می‌شود. روی ایران هم `client connected` هر ۶۰ ثانیه تکرار می‌شود.

علت: rbridge برای هر فوروارد (و یکی برای iperf) تا ۵۱۲ استریم از پیش باز نگه می‌دارد، و سرور Hysteria به‌طور پیش‌فرض حداکثر ۱۰۲۴ استریم همزمان قبول می‌کند (`quic.maxIncomingStreams`). با بیش از ۲ قانون rbridge این سقف رد می‌شود. این رفتار با Hysteria v2.13.0 در آزمایش بازتولید شد: با ۳ قانون خطا ظاهر شد و با `maxIncomingStreams: 8192` از بین رفت.

از نسخهٔ 0.9.0 تانل‌های reverse با `maxIncomingStreams: 8192` ساخته می‌شوند. برای تانل‌های قدیمی: منوی مدیریت، گزینهٔ 6، گزینهٔ 4 (Re-apply)، که کانفیگ سرور را بازنویسی و ری‌استارت می‌کند.

### `UDP 443 is busy`
خبر خوب است: اسکریپت خودکار به 8443 و در صورت نیاز به پورت تصادفی می‌رود.

### `port 80 busy` هنگام صدور گواهی
سرویسی که روی پورت 80 است را موقتاً متوقف کن. اسکریپت منتظر می‌ماند و بعد ادامه می‌دهد.

### `rbridge got no stream from the other side`
معمولاً نتیجهٔ شکست Hysteria است. ابتدا لاگ Hysteria را نگاه کن.

### `invalidContact` از Let's Encrypt
ایمیل ACME نامعتبر است. پیش‌فرض `admin@<دامنه>` است.

### چک‌لیست ✖ دارد
هر مورد ✖ دلیلش را کنارش نشان می‌دهد. تا همه ✔ نشوند، بنچمارک شروع نمی‌شود.

### نمایش لاگ یک سرویس
```bash
journalctl -u tm-<نام>-direct-hy.service -n 50 --no-pager
```
روی خارج هم همین دستور را روی سرور خارج اجرا کن.

## ۱۵. حالت دستی

اگر SSH به خارج ممکن نباشد، اسکریپت دستورهای لازم برای خارج را یکی‌یکی نشان می‌دهد. تو این دستورها را در ترمینال خارج اجرا می‌کنی و بعد با Enter ادامه می‌دهی. در این حالت بنچمارک فعال نیست، چون بنچمارک به SSH نیاز دارد.

## ۱۶. محدودیت‌ها و نکات مهم

- **پورت UDP باید از سمت مقابل باز باشد.** اسکریپت پورت‌ها را روی سرور خودش بررسی می‌کند، ولی فایروال ارائه‌دهنده و مسیر بین دو سرور را نمی‌تواند ببیند.
- **تست hop فقط جهت reverse را می‌سنجد.** یعنی بررسی می‌کند که پورت‌های بازهٔ hop روی ایران از خارج جواب می‌دهند. جهت direct (ایران به خارج) هنوز تست جدا ندارد.
- **ECH public name** را خودت باید انتخاب کنی. اسکریپت از داخل ایران نمی‌تواند آن را تست کند. نامی را انتخاب کن که واقعاً وجود داشته و معمولی باشد، و دامنهٔ خودت نباشد.
- **max-stealth** به دامنه با رکورد A نیاز دارد. بدون آن، ACME گواهی نمی‌دهد.
- **mimic حذف شده است.** هیچ پروفایلی آن را استفاده نمی‌کند.
- Hysteria روی نسخهٔ **v2.13.0** تست شده است (در آزمایشگاه و روی سرورهای واقعی).
